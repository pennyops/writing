If your x402 client worked last spring and now chokes on a `402`, the server has probably moved to x402 **version 2**. The flow is the same (request, get 402, sign, retry), but most field names and both headers changed. Here's the diff I wish I'd had, taken from the v1 and v2 spec documents and checked against a live v2 endpoint I run.

## 1. Headers

| What | v1 | v2 |
|---|---|---|
| Server says "pay me" | JSON body of the 402 | `PAYMENT-REQUIRED` response header (base64 JSON). Many servers also still put it in the body |
| Client sends payment | `X-PAYMENT` request header | `PAYMENT-SIGNATURE` request header |
| Server returns settlement | `X-PAYMENT-RESPONSE` | `PAYMENT-RESPONSE` |

Tip: during the transition, servers often send both `X-PAYMENT-RESPONSE` and `PAYMENT-RESPONSE`. Clients should read either one.

## 2. The 402 object (`PaymentRequired`)

v1:

```json
{
  "x402Version": 1,
  "error": "X-PAYMENT header is required",
  "accepts": [{
    "scheme": "exact",
    "network": "base-sepolia",
    "maxAmountRequired": "10000",
    "resource": "https://api.example.com/premium-data",
    "mimeType": "application/json",
    "outputSchema": null,
    "maxTimeoutSeconds": 60,
    "payTo": "0x...",
    "asset": "0x...",
    "extra": {"name": "USDC", "version": "2"}
  }]
}
```

v2:

```json
{
  "x402Version": 2,
  "error": "PAYMENT-SIGNATURE header is required",
  "resource": {
    "url": "https://api.example.com/premium-data",
    "description": "Access to premium market data",
    "mimeType": "application/json"
  },
  "accepts": [{
    "scheme": "exact",
    "network": "eip155:84532",
    "amount": "10000",
    "asset": "0x...",
    "payTo": "0x...",
    "maxTimeoutSeconds": 60,
    "extra": {"name": "USDC", "version": "2"}
  }],
  "extensions": {}
}
```

Field by field:

| v1 | v2 | Note |
|---|---|---|
| `accepts[].maxAmountRequired` | `accepts[].amount` | still a string in atomic units (USDC: 6 decimals, so "10000" = $0.01) |
| `accepts[].network: "base"` | `accepts[].network: "eip155:8453"` | CAIP-2 IDs. Base Sepolia = `eip155:84532` |
| `accepts[].resource` (string) | top-level `resource.url` | resource info moved out of each option into one object |
| `accepts[].mimeType`, `description` | `resource.mimeType`, `resource.description` | same |
| (none) | `extensions` | optional extension data. Clients echo it back |

## 3. The payment payload (what you base64 into the header)

v1 repeated `scheme` and `network` at the top level. v2 echoes the **whole option you picked** as `accepted`:

```json
{
  "x402Version": 2,
  "resource": {"url": "https://api.example.com/premium-data"},
  "accepted": { "...the exact accepts[] entry you chose...": "" },
  "payload": {
    "signature": "0x...",
    "authorization": {
      "from": "0xYou", "to": "0xPayTo", "value": "10000",
      "validAfter": "1740672089", "validBefore": "1740672154",
      "nonce": "0x<32 random bytes>"
    }
  },
  "extensions": {}
}
```

The `payload.authorization` part (an EIP-3009 `TransferWithAuthorization` signed as EIP-712 typed data) **did not change** for the `exact` EVM scheme, so your signing code can stay as it is. Only the envelope around it changed.

## 4. Minimal client patch (Python)

```python
import base64, json

def parse_402(resp):
    h = resp.headers.get("PAYMENT-REQUIRED")
    pr = json.loads(base64.b64decode(h)) if h else resp.json()
    opt = pr["accepts"][0]
    amount = opt.get("amount") or opt.get("maxAmountRequired")   # v2 / v1
    return pr, opt, int(amount)

def payment_header(pr, opt, signed_payload):
    if pr.get("x402Version", 1) >= 2:
        body = {"x402Version": 2, "resource": pr.get("resource"),
                "accepted": opt, "payload": signed_payload}
        name = "PAYMENT-SIGNATURE"
    else:
        body = {"x402Version": 1, "scheme": opt["scheme"],
                "network": opt["network"], "payload": signed_payload}
        name = "X-PAYMENT"
    return name, base64.b64encode(json.dumps(body).encode()).decode()
```

And for the EIP-712 domain, map the network to a chain ID: with v2 that's simply `int(opt["network"].split(":")[1])` for `eip155:*`, which beats keeping a name table like v1 needed.

## 5. Checklist

- [ ] Read `PAYMENT-REQUIRED` header first, body as fallback
- [ ] `amount` with `maxAmountRequired` fallback
- [ ] CAIP-2 network parsing (`eip155:8453`)
- [ ] Send `PAYMENT-SIGNATURE` (v2) / `X-PAYMENT` (v1) based on `x402Version`
- [ ] Echo the chosen option as `accepted`, plus `resource` and `extensions`
- [ ] Read `PAYMENT-RESPONSE` or `X-PAYMENT-RESPONSE`
